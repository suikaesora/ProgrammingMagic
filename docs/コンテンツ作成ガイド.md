# コンテンツ作成ガイド

修行の文章や課題を入れるときの手引きです。**コンテンツはすべて `content/` フォルダ**にあり、システム側（`js/`）を触らなくても編集できます。

## 1. ローカルで確認する

ES Modules を使っているため、`index.html` をダブルクリックで開いても動きません。プロジェクトのフォルダで次を実行し、ブラウザで開いてください。

```
python tools/devserver.py
```

→ http://127.0.0.1:8000/ を開く（キャッシュ無効なので、保存してリロードすれば反映されます）

### 確認に便利なコンソール命令（ブラウザの開発者ツールで）

| 命令 | 内容 |
|---|---|
| `__app.open(10, 'task')` | 指定の修行だけを開く。1つ目は修行番号か ID（`'l10'`）、2つ目は `'explain'`（解説・省略時）か `'task'`（課題）。まだ解放していない修行も開ける（このタブを閉じるか `__app.closePreview()` までのあいだ）。開いた修行はクリアしても、クリア済み・アイテム入手として記録しない（クリア画面は出るが「次の修行へ」は出ない）。開くたびに、その修行の行隠し・お手本実行は最初の状態にもどる。書いたコードの下書きは保存される |
| `__app.closePreview()` | `__app.open` で開いた修行を、ふつうの状態（記録する・解放ルールどおり）にもどす |
| `__app.lessons()` | 修行の番号・ID・名前の一覧を表示 |
| `__app.unlockAll()` | 全修行をクリア済みにする（アイテムも入手） |
| `__app.reset()` | 進捗をすべて消して導入部からやり直す |
| `__app.state()` | 保存内容を表示 |
| `__app.runner.result()` | 直前の実行結果（check に渡される内容）を見る |

## 2. ファイルの役割

| ファイル | 内容 |
|---|---|
| `content/config.js` | 教材名、キャンバスサイズ、師匠・見た目の画像、認定証画像のパス、宝箱のルール（`chestRule`、課題の途中で解説を見たときに減らす数 `explainPenalty`）、課題のお手本をコピーできるか（`allowSampleCopy`）など |
| `content/story.js` | 導入部の物語文、見た目選択の文言、最終課題クリア後のエピローグ |
| `content/lessons/index.js` | 修行の並び（この順番が修行番号。0番目が練習部）。内容は `docs/教材修行設計概要.md` にそっている |
| `content/lessons/lessonXX.js` | 各修行のデータ |
| `content/tutorial.js` | 練習部（修行0）の手順 |
| `content/items.js` | コレクションアイテム。画像は `assets/items/修行ID-何番目`（例：修行4の2つ目 → `l04-2.png`） |
| `content/sprites.js` | `render()` で描ける画像の登録（下の 5-1 参照） |
| `content/commands.js` | 命令の書き方の説明（課題画面の「つかう命令」メモに出る） |
| `css/theme.css` | 色・線・角丸・フォント（見た目の基準ファイル） |
| `assets/` | 画像（キャラ・アイテム・師匠・認定証は仮の PNG。同じ名前の PNG で上書きすれば差し替わる。`icons/` と `favicon.svg` は UI 用の SVG） |

## 3. 修行を追加する

1. `content/lessons/lesson03.js` などをコピーして `lesson04.js` を作る
2. `id` を重複しないものにする（例：`'l04'`）
3. `content/lessons/index.js` で import して配列に加える

## 4. 修行データの項目

```js
export default {
  id: 'l04',                 // 一意の ID（保存データのキーになるので、公開後は変えない）
  label: '練習',             // 省略可。番号の代わりに表示する文字
  title: '修行名',
  summary: '選択画面に出る一言説明',
  difficulty: 2,             // 難易度（星 1〜5）
  items: ['star', 'hat', 'moon'],  // 宝箱の中身（items.js の id。最大3つ。宝箱1個なら先頭の1つ）

  // 全体コード：/*@USER@*/ の位置に、お手本コード（解説）や学習者のコード（課題）が入る。
  // ここで定義した変数・関数は学習者のコードから使える。省略すると '/*@USER@*/' だけ。
  template: `const ground = 320;\n/*@USER@*/`,

  explain: {
    html: `<h2>見出し</h2><p>本文（HTML）</p>`,   // 文章解説エリア
    sampleCode: `circle(200, 200, 50);`,           // お手本コード
    master: ['台詞1', '台詞2'],                    // 師匠の台詞（「つぎ」で送る）
    lineIcons: { 1: 'assets/icons/point.svg' },    // 省略可。行番号の横のアイコン
    template: `...`,                               // 省略可。解説だけ別の全体コードにしたいとき
  },

  task: {
    problemHtml: `<h3>課題</h3><p>…</p>`,          // 問題エリア
    answerCode: `...`,                             // 課題のお手本（行隠し付きで表示）
    hiddenLines: [2, 3, 5],                        // 行隠しを入れる行（1始まり）。省略すると約8割を自動
    starterCode: '',                               // コード記述エリアの最初の中身
    sprites: ['ren', 'slime'],                     // 省略可。「つかう命令」の render の下に見本を出す画像（省略するとすべて）
    master: ['課題中の師匠の台詞'],
    failMessage: '実行しても未クリアのときの師匠の台詞',
    refs: ['circle', 'fill', { sig: 'drawGround()', desc: '地面をかく' }],  // 「つかう命令」メモ（下の 4-1 参照）
    lineIcons: {},                                 // 省略可
  },

  // クリア判定（true を返すとクリア）
  check(result) {
    return result.vars.size === 60;
  },
};
```

### 4-1. 「つかう命令」メモ（task.refs）

課題画面の問題エリアの右に、その課題で使う命令の書き方を表示します。**見ても宝箱は減りません。**
課題中に解説を見ると宝箱が減るので、「circle の引数の順番を忘れた」のような、課題の本題ではない知識で詰まらないようにするためのものです。

- `content/commands.js` にある名前を並べると、その説明が出ます（例：`'circle'`）
- その修行だけの関数・変数（`template` で用意したものなど）は `{ sig: '書き方', desc: '説明' }` で直接書けます
- 答えに使う組み込み命令は、原則すべて refs に入れてください

### 4-2. 課題を作るときの注意

- **課題で必要な知識は、その修行の解説か、それより前の修行で教えたものだけにする。** 新しい命令やキー名などを課題で初めて使わせない
- **お手本（answerCode）には、課題文で求めていないものを入れない。** 例：課題文で色を指定していないのに `fill("skyblue")` を入れると、学習者は「色も必要なのか」と迷う
- **解説のお手本コードは、課題の答えそのものにしない。** 同じ書き方を、別の場面（別のキー・別の図形など）で見せる
- **hiddenLines はなるべく指定する。** 省略したときの自動の行隠しは、行を均等に間引くだけで、どの行が大事かは考えない。答えのかなめの行が見えたままになることがあるので、実際に画面で確かめる。starterCode と同じ行は隠しても意味がない

### check(result) で使えるもの

`check` は「プログラムの本体が最後まで動いたとき」と「onFrame の各フレームの後」に呼ばれます。

| 項目 | 内容 |
|---|---|
| `result.vars` | 全体コードの一番外側で作られた変数の値（例：`result.vars.x`） |
| `result.logs` | `print()` で出力した文字列の配列 |
| `result.keys` | `waitKey()` で受け取ったキーの配列（押した順） |
| `result.drawCalls` | 描画命令の記録 `{ type, args, fill, stroke }` の配列。type は `circle` `rect` `ellipse` `line` `text` `background` `clear` |
| `result.frames` | onFrame が実行された回数 |
| `result.count('circle')` | その種類の描画命令の回数 |
| `result.find('circle', c => c.args[2] === 80)` | 条件に合う描画命令の配列 |

例：

```js
// 「こんにちは」と表示したか
check: (r) => r.logs.includes('こんにちは'),
// 円を10個以上かいたか
check: (r) => r.count('circle') >= 10,
// 赤い四角をかいたか
check: (r) => r.find('rect', (c) => c.fill === 'red').length > 0,
```

## 5. 学習者が使える命令

| 命令 | 内容 |
|---|---|
| `print(値, …)` | 出力エリアに表示 |
| `background(色)` | 画面全体を塗る |
| `fill(色)` / `noFill()` | 塗りの色 / 塗らない |
| `stroke(色, 太さ)` / `noStroke()` | 線の色 / 線なし |
| `circle(x, y, 半径)` | 円 |
| `ellipse(x, y, 横半径, 縦半径)` | だ円 |
| `rect(x, y, 幅, 高さ)` | 四角形 |
| `line(x1, y1, x2, y2)` | 線 |
| `text(文字, x, y, 大きさ)` | 文字 |
| `render(x, y, "画像名", 幅)` | 登録した画像。(x, y) が画像のまんなか。幅は省略可（縦横比はそのまま） |
| `random(最小, 最大)` / `randomInt(最小, 最大)` | 乱数 |
| `onFrame(関数)` | 毎フレーム（約60回/秒）実行する関数を登録 |
| `keyIsDown("ArrowRight")` | キーが押されているか（キャンバスをクリックしてから） |
| `let key = waitKey();` | キーが押されるまで待ち、押されたキーの名前を返す（下の 5-2 参照） |
| `mouseX()` / `mouseY()` / `mouseIsPressed()` | マウス |
| `WIDTH` / `HEIGHT` | キャンバスの大きさ（400） |
| `ctx` | Canvas 2D コンテキスト（上級者向け） |

命令を増やすときは `js/runner/runtimeApi.js` の `api` に関数を追加します（描画なら `record()` も呼ぶと check で使えます）。あわせて `content/commands.js` にも説明を追加すると、課題の「つかう命令」メモで使えます。

### 5-1. 画像を追加する（render 用）

1. 画像を `assets/sprites/` に置く。**背景が透明な PNG** にする。表示する幅の4倍くらいの大きさで描くとくっきり出る（例：`width: 80` なら 320px 前後）
2. `content/sprites.js` に1行足す
   ```js
   dragon: { image: 'assets/sprites/dragon.png', width: 120, name: 'ドラゴン' },
   ```
   - 左の名前（`dragon`）が、コードで書く画像名になる：`render(200, 150, "dragon")`
   - `width` は幅を省略したときの幅（キャンバスは 400×400）。高さは画像の縦横比から自動で決まる
   - `name` は課題画面の「つかう命令」メモに出す表示名
3. 課題で使うときは `task.refs` に `'render'` を入れる。「つかう命令」メモに、登録したすべての画像が見本つきで並ぶ

画像はアプリの起動時にまとめて読み込まれ、読み込みが終わってから実行されます。登録されていない名前を書くと「画像「○○」は登録されていません。使える画像：…」というエラーになります。

いま入っている画像（`slime`・`dragon`・`fire`・`gu` など）は仮の画像です。同じ名前のファイルを置けば差し替わります（拡張子を変える場合は `content/sprites.js` のパスも直す）。

`ren`（レン）は `avatar: true` になっていて、プレイヤーが導入部で選んだ姿（`config.avatars` の画像）で描かれます。`zork`（ゾルク）は師匠の画像（`assets/master/master.png`）です。

check の例：
```js
// スライムを描いたか
check: (r) => r.find('render', (c) => c.args[2] === 'slime').length > 0,
// args は [x, y, 画像名, 幅, 高さ]
```

### 5-2. キー入力を待つ（waitKey）

```js
let key = waitKey();   // キーが押されるまで、ここで止まって待つ
if (key === "1") { … }
```

- 押されたキーの名前（`"1"` `"a"` `" "` `"ArrowUp"` `"Enter"` など）が返ります。日本語入力がオンでも、数字と英字は半角の名前になります
- `while` や `for` の中、学習者が作った関数の中でも使えます。ターン制のゲーム（じゃんけん・バトル）はこれで作れます
- `onFrame` にわたした関数の中や、`obj.名前() { }` の形で書いた関数の中では使えません（エラーになります）。メインループの中では `keyIsDown()` を使ってください
- 待っている間、コントロールパネルには「キーを押してね」と出ます
- check は「キー待ちに入るたび」と「最後まで動いたとき」に呼ばれます。`result.vars` は最後まで動いたときにだけ入るので、キーを使う課題では `result.keys` と組み合わせて判定します（`lesson04.js`・`lesson11.js` が例）

## 6. 練習部の手順（content/tutorial.js）

```js
{ scene: 'explain', target: 'btn-run', advance: 'event:run:start', text: '「実行」を押してみよう' }
```

- `scene`: `'explain'` か `'task'`
- `target`: 光らせる場所（ファイル冒頭のコメントに一覧あり）。`null` で中央に吹き出し
- `advance`: `'next'`（次へボタン）または `'event:名前'`（その操作で進む）
- `block: false` にすると、光らせた場所以外も操作できる

## 7. 見た目を変える

- 色・線の太さ・角丸・フォントは **`css/theme.css` だけ**で変えられます（ライト / ダーク両方）。
- 画像は `assets/` の PNG を、同じ名前の PNG（背景は透明）で上書きすれば差し替わります。名前や形式を変えたいときは `config.js` / `items.js` / `sprites.js` のパスを書き換えます。
- 縦横比がちがう画像に差し替えても、ゆがまずに表示されます（はみ出さないように縮めて表示）。
- 目安の大きさ：アイテム 400×400、見た目（アバター）480×600、師匠 480×480、認定証 2400×1700。
- アイテム画像のファイル名は修行番号と何番目かで決まっています（`assets/items/l00-1.png` 〜 `l11-3.png`）。修行の `items: [...]` に並べた順が 1・2・3 番目です。
- 認定証は `assets/certificate.png`（パスは `config.js` の `certificateImage`）。

## 8. 実行のしくみ（参考）

- **通常実行**：コードを Acorn で解析し、各文の前に行番号の記録と無限ループ防止を差し込んでから実行します。
- **キー入力待ち（waitKey）**：`waitKey` を使うコードは、通常実行でもインタプリタ実行と同じジェネレータ版で動かし、止まらずに進めて、キー待ちのところでだけ止まります。
- **インタプリタ実行**：コード全体をジェネレータに変換し、学習者のコードの各文の前で一時停止します。学習者が書いた関数（アロー関数を含む）の中にも入って1行ずつ進みます。ただし `forEach` などの標準関数から呼ばれた関数の中は一気に実行されます。
- 学習者のコードからは `window` / `document` / `localStorage` などは見えないようにしてあります（完全な隔離ではありません）。
